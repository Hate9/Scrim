## Q-025: X-1 screenshot comparison and blocks the export leaves out
**Asked by:** implementation, 2026-11-22
**Question:** X-1 compares a screenshot of the HTML export (loaded at the editor's width)
with the editor's (all blocks collapsed, cursor in no block): at most 2% of pixels may
differ. The feature document (20) must contain every block of 04, including some that
the editor shows but an export does not contain:

- front matter (4.11): the editor shows its YAML; 9.1 renders the document without it,
- link reference definitions (4.14): shown as a block in the editor, not content,
- an HTML comment block (4.10): the editor shows a placeholder, the export the comment
  only (invisible).

Each shifts everything below it, so a whole-page comparison fails on them alone,
however exact the rendering is. Is the intent:

1. the editor screenshot is taken with those blocks hidden (they are not part of the
   exported content), or
2. the export keeps them in some visible form, or
3. X-1 compares block by block (each exported block against the same block in the
   editor)?

Also, X-1 says "loaded in Scrim's own hidden webview". A hidden window cannot be
screenshotted through WebDriver; the test loads the export page in an iframe of the
document window instead (the same webview engine and settings, at the editor's
width). Is that acceptable?

**Interim behavior:** option 1, with the iframe. The X-1 test hides the front matter,
link definitions, and comment placeholders in the editor before its screenshot.
Footnote definitions are at the end of the feature document in both.
