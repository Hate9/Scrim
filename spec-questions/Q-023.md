## Q-023: Default horizontal rule renders darker in WebKitGTK than in the reference
**Asked by:** implementation, 2026-11-22
**Question:** Q-022 asks to find and remove what in Scrim draws orangeheart's solid
dark rule. Nothing in Scrim does. With orangeheart (and with an empty theme) the
`hr` inside `div.md-hr` has exactly the browser defaults, and no Scrim rule matches
either element (checked through the CSSOM in the running app):

| | `color` | `border-style` | `border-width` | margins | drawn rows (top, bottom) |
|---|---|---|---|---|---|
| Scrim (WebKitGTK) | `rgb(128,128,128)` | `inset` | `1px` | `0.5em` | `#2C2C2C`, `#D4D4D4` |
| Chromium, plain `<hr>` | `rgb(128,128,128)` | `inset` | `1px` | `0.5em` | `#9A9A9A`, `#EEEEEE` |

So the difference is how each engine shades an `inset` border: WebKitGTK darkens the
top edge almost to black, Chromium only slightly. The spacing comes from the same
`0.5em` margins (7px at orangeheart's 14px) collapsing with the paragraph margins as
usual; I found no Scrim rule that changes it, so any spacing difference in the
candidate is the same as the reference's unless the spec team can point to the spot.

Matching the reference needs a base rule after all, against 10.3 "no base styling".
Options:
1. Leave the engine default (current behavior): themes without an `hr` rule show a
   darker line than in the reference; orangeheart's golden is approved as it is.
2. A zero-specificity base rule that reproduces Chromium's shading:
   `:where(hr) { border-style: solid; border-width: 1px; border-color: #9a9a9a #eee
   #eee #9a9a9a }`. Any theme `hr` rule wins over it. A theme that sets only `color`
   on `hr` (expecting an inset line in that color) would then still get gray.
3. Like 2, but derived from the current color so option 2's last caveat goes away:
   `border-color: color-mix(in srgb, currentColor 80%, white) color-mix(in srgb,
   currentColor 13%, white) …`, which gives `#9A9A9A`/`#EEEEEE` for gray.

**Interim behavior:** option 1 (no base rule), marked `SPEC-QUESTION Q-023` in
`src/styles.css`. T-1 candidates stay as on `goldens/2026-11-22-d506069`.
